# Auto-Improve 知识库

> AI 每轮改进后记录学到的经验，供下一轮参考。

## 项目架构要点

- vault.py 是核心入口（God Object，933 行），改它要小心
- site/ 已拆成包（mkdocs_config, wikilinks, graph, deploy, resources）
- async/sync 混用是重灾区，飞书通道每条消息创建新 event loop
- LLM 客户端有两套获取方式（_get_llm_client 全局单例 vs vault 实例级），容易配置不一致
- MCP skill 注册是硬编码 if/elif，新增 skill 必须改 mcp.py

## 已知问题（不要重复修）

- MiniMax API 在 NAS 上频繁 529，是 MiniMax 服务端问题不是代码问题
- 概念中英文混合（如 AWQ量化）已通过 _is_junk_concept 过滤
- 双链替换曾破坏源文件，已改为写到 _build_docs 目录
- Dockerfile 构建顺序已修复

## 敏感区域（改动需谨慎）

- akasha/llm.py — Semaphore 限流，改并发逻辑前想清楚
- akasha/serve/feishu.py — 飞书消息处理，改消息路由要考虑去重
- akasha/site/graph.py — AntV G6 模板用字符串拼接不用 f-string（Jinja2 冲突）
- akasha/vault.py:_on_pages_created — post_save hook 是 async，调用链全是 await

## 代码规范

- Python 3.12+，用 type hints
- async 函数不要用 asyncio.run()，用 await
- 新文件写完要跑语法检查
- 概念双链统一英文名
- 页面标题最长 30 字符，文件名最长 40 字符
